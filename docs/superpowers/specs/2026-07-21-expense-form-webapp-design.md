# ระบบกรอกฟอร์มเบิกจ่ายออนไลน์ — โกลบ ซินดิเคท (ประเทศไทย)

เอกสารออกแบบ (Design Spec) · วันที่ 2026-07-21 · ปรับปรุง flow ครั้งที่ 2

---

## 1. ภาพรวมและเป้าหมาย

ปัจจุบันพนักงานแต่ละคน/แผนกใช้ไฟล์ฟอร์มเบิกจ่ายชุดเดียวกัน แต่กรอกในรูปแบบที่ไม่เหมือนกัน
ทำให้เอกสารที่ส่งเข้าฝ่ายบัญชีมีหน้าตาหลากหลาย ตรวจสอบยาก

**เป้าหมาย:** สร้างเว็บให้พนักงานเข้ามากรอกข้อมูลผ่านฟอร์มมาตรฐานเดียวกัน แล้วออกเป็นไฟล์ **PDF**
และ **สั่งพิมพ์ได้ในระบบ** พร้อมเก็บประวัติเอกสารทั้งหมด (แก้ไขย้อนหลัง + พิมพ์ใหม่ได้)
และมีฝั่ง **Admin** สำหรับดูข้อมูลพนักงานและประวัติการพิมพ์ของทุกคน

**สิ่งที่วัดผลว่าสำเร็จ:**
- พนักงาน login ด้วยรหัสพนักงาน แล้วกรอกฟอร์ม "ใบเบิกค่าใช้จ่าย" จนออก PDF / สั่งพิมพ์ได้
- ไฟล์ที่ออกมาหน้าตาตรงกับฟอร์มต้นฉบับของบริษัท
- ทุกใบถูกบันทึก เปิดดู/แก้ไข/พิมพ์ใหม่ได้ภายหลัง
- ระบบคำนวณยอดเงิน หักภาษี และแปลงจำนวนเงินเป็นตัวอักษรไทยให้อัตโนมัติ
- Admin เห็นรายชื่อพนักงานและประวัติว่าใครพิมพ์ใบไหนไปแล้วบ้าง

## 2. ผู้ใช้ / บทบาท (Roles) และขอบเขต MVP

**2 บทบาท:**
- **พนักงาน (employee):** กรอกฟอร์ม, ออก PDF, สั่งพิมพ์, ดู/แก้ไข/พิมพ์ใหม่เฉพาะเอกสารของตัวเอง, เปลี่ยนรหัสผ่านตัวเอง
- **แอดมิน (admin):** ทำได้ทุกอย่างของพนักงาน + ดูข้อมูลพนักงานทั้งหมด + ดูประวัติการพิมพ์ของทุกคน + จัดการบัญชีพนักงาน

**ขอบเขต MVP — ทำ 1 ฟอร์มให้จบวงจรก่อน:**
- ฟอร์มเดียว: **ใบเบิกค่าใช้จ่าย** (รหัส GAC6709-003)
- วงจรครบ: login → เลือกฟอร์ม → กรอก → preview → บันทึก → ออก PDF / สั่งพิมพ์ → หน้าประวัติ (แก้ไข+พิมพ์ใหม่)
- ฝั่ง admin: รายชื่อพนักงาน + ประวัติการพิมพ์ทั้งหมด

**หลัง MVP:** เพิ่มฟอร์มที่เหลืออีก 8 ตัว + ฟอร์มแผนก Design Experience (รอไฟล์) — ดูข้อ 12

## 3. Tech Stack

| ส่วน | เทคโนโลยี |
|---|---|
| Frontend | React + Vite + TypeScript + Tailwind CSS |
| Auth | Firebase Authentication (email/password) — ใช้รหัสพนักงานแทน username |
| Database | Cloud Firestore |
| Hosting | Firebase Hosting |
| สร้าง PDF | @react-pdf/renderer + ฟอนต์ไทย Sarabun (ฝั่ง browser) |
| สั่งพิมพ์ | พิมพ์ผ่าน browser (window.print กับ layout สำหรับพิมพ์ หรือเปิด PDF แล้วพิมพ์) |
| แปลงจำนวนเงินเป็นตัวอักษรไทย | ไลบรารี bahttext (หรือฟังก์ชันของเราเอง) |

**หลักการสำคัญ:** สร้าง PDF ที่ฝั่ง browser (client-side) → **ไม่ต้องมี backend / Cloud Functions**
ใช้แค่ Hosting + Auth + Firestore ซึ่งอยู่ในโควตาฟรี/ราคาถูก เหมาะกับงานภายใน
**ยกเลิกการ export Excel แล้ว** (เหลือ PDF + สั่งพิมพ์)

## 4. สถาปัตยกรรมและโครงสร้างข้อมูล

### 4.1 Flow การทำงาน
1. ผู้ใช้ login ด้วย **รหัสพนักงาน + รหัสผ่าน** — ระบบดูบทบาท (employee/admin) จากโปรไฟล์
2. **ฝั่งพนักงาน:**
   - เลือกฟอร์ม (MVP มีตัวเดียว) → กรอก (ข้อมูลส่วนตัว auto-fill จากโปรไฟล์)
   - ระบบคำนวณยอด/หักภาษี/ตัวอักษรไทย อัตโนมัติแบบ real-time
   - Preview → บันทึกลง Firestore (ออกเลขที่เอกสารอัตโนมัติ) → ออก PDF / กดสั่งพิมพ์
   - หน้าประวัติ: ดูใบเก่าของตัวเอง → **แก้ไข (ทับของเดิม)** → พิมพ์ใหม่
   - ปุ่มเปลี่ยนรหัสผ่านของตัวเอง
3. **ฝั่งแอดมิน:**
   - ดูรายชื่อพนักงานทั้งหมด + ข้อมูลโปรไฟล์
   - ดูประวัติการพิมพ์: ใครพิมพ์ใบไหน เมื่อไหร่ ยอดเท่าไหร่
   - จัดการบัญชีพนักงาน (เพิ่ม/รีเซ็ตรหัส — ดูข้อ 5)

### 4.2 Data model (Firestore)
```
companies/{companyId}       // ตั้งค่าตั้งต้นโดย admin (seed อย่างน้อย 2 แห่ง)
  name                         // เช่น "บริษัท โกลบ ซินดิเคท (ประเทศไทย) จำกัด"
  address                      // ที่อยู่ที่ขึ้นหัวฟอร์ม

users/{uid}
  employeeId                   // รหัสพนักงาน (ใช้ login)
  firstName, lastName          // ชื่อ / นามสกุล (auto-fill)
  position                     // ตำแหน่ง
  department                   // แผนก
  companyId                    // สังกัดบริษัท → หัวฟอร์มดึงชื่อ+ที่อยู่จากตรงนี้
  defaultJob                   // Job/สังกัดเริ่มต้น (แก้ได้ตอนกรอก)
  bankAccount                  // เลขบัญชี (ถ้าใช้ประจำ)
  role                         // "employee" | "admin"
  mustChangePassword           // true ถ้ายังใช้รหัสเริ่มต้น (= รหัสพนักงาน)
  createdAt

submissions/{submissionId}
  formType         // "expense-claim" (GAC6709-003)
  docNumber        // เลขที่เอกสารอัตโนมัติ เช่น "GAC6709-003-2607-0001"
  header {         // ส่วนหัวฟอร์ม
    subject, categories[], firstName, lastName, position, job
  }
  items[ {        // รายการ line items
    date, seq, pcCode, pcName, workDays, ratePerDay,
    bankAccount, pcType, job, amountBeforeWht, wht3, amountNet, applyWht
  } ]
  totals { totalBefore, totalWht, totalNet, amountInThaiText }
  createdBy        // uid ของพนักงานเจ้าของ
  createdByEmployeeId
  createdAt
  updatedAt        // อัปเดตเมื่อแก้ไขย้อนหลัง (ทับของเดิม)
  printCount       // จำนวนครั้งที่พิมพ์ (นับให้ admin เห็น)
  lastPrintedAt

counters/{formType}
  lastNumber       // ตัวนับเลขรันเอกสาร (อัปเดตด้วย Firestore transaction)
```

### 4.3 การแก้ไขย้อนหลัง
- เปิดใบเก่า → แก้ไข → กดบันทึก = **ทับของเดิม** (อัปเดต document เดิม, ตั้ง `updatedAt`)
- เลขที่เอกสาร (`docNumber`) คงเดิม, พิมพ์ใหม่ได้ (เพิ่ม `printCount`)

### 4.4 การออกเลขที่เอกสารอัตโนมัติ
ใช้ Firestore **transaction** อ่าน `counters/{formType}.lastNumber` แล้ว +1 พร้อมเขียน `submissions`
เพื่อกันเลขซ้ำเมื่อมีคนกดพร้อมกัน (ทำที่ client ผ่าน `runTransaction`)

## 5. Authentication และความปลอดภัย

- **Login:** รหัสพนักงาน + รหัสผ่าน
- **เบื้องหลัง:** ใช้ Firebase Auth (email/password) โดย map รหัสพนักงานเป็นอีเมลสังเคราะห์ภายใน เช่น
  `{employeeId}@globe.local` (ผู้ใช้ไม่เห็น/ไม่ต้องรู้อีเมลนี้ — กรอกแค่รหัสพนักงาน) → ได้ประโยชน์จากระบบ
  hash รหัสผ่าน + session ของ Firebase โดยไม่ต้องสร้างเอง
- **รหัสเริ่มต้น:** รหัสผ่านตั้งต้น = รหัสพนักงาน (ตั้ง `mustChangePassword = true`) → พนักงานควรเปลี่ยนเมื่อเข้าครั้งแรก
- **ปุ่มเปลี่ยนรหัสผ่าน:** พนักงานเปลี่ยนรหัสเองได้ (Firebase `updatePassword`)
- **การสร้างบัญชีพนักงาน:** แอดมินเป็นผู้เพิ่มบัญชี (กรอกรหัสพนักงาน+ข้อมูลโปรไฟล์ ระบบตั้งรหัสเริ่มต้นให้)
  หรือแอดมิน reset รหัสให้กรณีลืม
- **Firestore Security Rules:**
  - `users/{uid}` — เจ้าของอ่าน/แก้โปรไฟล์ตัวเองได้; admin อ่านได้ทั้งหมด
  - `submissions` — พนักงานอ่าน/แก้ได้เฉพาะที่ `createdBy == auth.uid`; admin อ่านได้ทั้งหมด
  - บทบาท admin ตรวจจาก `users/{uid}.role == "admin"`
  - `counters` — เขียนผ่าน transaction เท่านั้น

## 6. ฟอร์ม MVP: ใบเบิกค่าใช้จ่าย (GAC6709-003)

### 6.1 ส่วนหัว
- **ชื่อบริษัท + ที่อยู่ (บนสุด):** ดึงอัตโนมัติจากบริษัทที่พนักงานสังกัด (`companyId` ในโปรไฟล์)
- **เรื่อง:** "ขออนุมัติเบิกค่าใช้จ่าย" (คงที่) + ติ๊กหมวด: ค่าไมล์เลทและค่าใช้จ่ายเดินทาง / ค่าใช้จ่ายต่างๆ / ค่าล่วงเวลา / ค่าเบี้ยเลี้ยง
- **เรียน:** "ท่านผู้จัดการ" (คงที่)
- **เลขที่เอกสาร:** ออกอัตโนมัติ
- **ชื่อ / นามสกุล / ตำแหน่ง / Job:** auto-fill จากโปรไฟล์ (แก้ไขได้)

### 6.2 ตารางรายการ (line items — เพิ่ม/ลบแถวได้)
คอลัมน์: วันเดือนปี · ลำดับ(อัตโนมัติ) · รายละเอียด (PC Code, PC Name, วันทำงาน, วันละ) · ธนาคาร ·
ประเภทพีซี · Job · จำนวนเงินก่อนหัก · หักภาษี ณ ที่จ่าย 3% · จำนวนเงินรวม(สุทธิ)

### 6.3 กฎการคำนวณ (อัตโนมัติ real-time)
- `จำนวนเงินก่อนหัก = วันทำงาน × วันละ`
- `หักภาษี ณ ที่จ่าย 3% = ROUND(จำนวนเงินก่อนหัก × 0.03, 2)` (ตั้งต่อแถวได้ว่าหัก/ไม่หัก, default = หัก)
- `จำนวนเงินรวม (สุทธิ) = จำนวนเงินก่อนหัก − หักภาษี 3%`
- `รวมทั้งสิ้น` = ผลรวมของแต่ละคอลัมน์ตัวเลขทุกแถว
- `เป็นจำนวนเงิน (ตัวอักษร)` = แปลงยอดสุทธิรวมเป็นข้อความภาษาไทย เช่น "หนึ่งหมื่นสามพันเก้าสิบห้าบาทถ้วน"

**การแก้ไขค่าที่คำนวณ (override):** ช่องที่คำนวณอัตโนมัติ (หักภาษี 3%, ยอดรวม ฯลฯ) จะ**ล็อกไว้เป็น
ค่าเริ่มต้น** เพื่อกันพิมพ์ผิด แต่มีปุ่ม/ติ๊ก "แก้เอง" ต่อแถว/ต่อช่อง เพื่อ**ใส่ค่าเองแทนสูตรได้**เมื่อจำเป็น
(เก็บ flag ว่าช่องไหนถูก override ไว้ในข้อมูล) — ใช้ได้ทั้งตอนกรอกใหม่และตอนแก้ไขในหน้าประวัติ

### 6.4 Validation
- ต้องมีอย่างน้อย 1 แถวที่มีจำนวนเงิน
- วันทำงาน/วันละ/จำนวนเงิน เป็นตัวเลข ≥ 0
- ต้องมีชื่อ–นามสกุล–ตำแหน่ง
- เตือน (ไม่บล็อก) หากไม่ได้ติ๊กหมวดค่าใช้จ่าย

### 6.5 ส่วนลายเซ็น (เว้นว่างไว้เซ็นจริง)
ผู้เบิก · หัวหน้าแผนก · ผู้อนุมัติ · ผู้รับเงิน · ผู้ตรวจสอบ/ฝ่ายบัญชี + ช่องวันที่ → พิมพ์เป็นช่องว่างให้เซ็นด้วยมือ

## 7. การออกเอกสาร: PDF และสั่งพิมพ์ (ไม่มี Excel)

### 7.1 PDF
- สร้าง layout ฟอร์มเป็น component ของ **@react-pdf/renderer** ฝังฟอนต์ไทย **Sarabun**
  (ตัวอักษรเป็น vector คมชัด ค้นหา/คัดลอกได้) → กดดาวน์โหลดไฟล์ .pdf

### 7.2 สั่งพิมพ์ในระบบ
- ปุ่ม "พิมพ์" — เปิด PDF ที่ generate แล้วสั่งพิมพ์ หรือใช้ layout สำหรับพิมพ์ (`@media print`) + `window.print()`
- ทุกครั้งที่พิมพ์ อัปเดต `printCount` / `lastPrintedAt` เพื่อให้ admin เห็นสถิติ

### 7.3 หน้า Preview
- React component (HTML) หน้าตาเลียนแบบฟอร์ม เพื่อให้ผู้ใช้ตรวจก่อนออก PDF/พิมพ์ (ใช้ข้อมูลชุดเดียวกัน)

## 8. หน้าจอ (Screens)

**ทั่วไป**
1. **Login** — กรอกรหัสพนักงาน + รหัสผ่าน
2. **เปลี่ยนรหัสผ่าน** — ปุ่มในเมนูผู้ใช้ (บังคับ/เตือนถ้ายังใช้รหัสเริ่มต้น)
3. **โปรไฟล์** — ชื่อ/นามสกุล/ตำแหน่ง/แผนก/Job เริ่มต้น

**ฝั่งพนักงาน**
4. **Dashboard** — การ์ดเลือกฟอร์ม + ปุ่มไปหน้า History
5. **หน้ากรอกฟอร์มใบเบิกค่าใช้จ่าย** — ส่วนหัว + ตาราง line items + ยอดสรุป real-time
6. **Preview** — ดูตัวอย่าง + ปุ่มบันทึก / ดาวน์โหลด PDF / พิมพ์
7. **History (ของตัวเอง)** — ตารางเอกสาร (เลขที่, วันที่, ยอด, จำนวนครั้งพิมพ์) + ปุ่ม แก้ไข / พิมพ์ใหม่ / ดาวน์โหลด PDF

**ฝั่งแอดมิน**
8. **รายชื่อพนักงาน** — ค้นหา/ดูโปรไฟล์พนักงานทุกคน + **เพิ่มพนักงานทีละคน** + **import CSV** + reset รหัส
9. **ประวัติการพิมพ์ทั้งหมด** — ทุกใบของทุกคน (กรองตามพนักงาน/วันที่/ฟอร์ม) ดูรายละเอียด/ดาวน์โหลด PDF

### 8.1 การเพิ่มพนักงาน (ฝั่งแอดมิน)
- **ทีละคน:** ฟอร์มกรอก รหัสพนักงาน, ชื่อ, นามสกุล, ตำแหน่ง, แผนก, บริษัท(companyId), Job, เลขบัญชี, role
- **Import CSV:** อัปโหลดไฟล์ที่มีคอลัมน์: `employeeId, firstName, lastName, position, department,
  companyId, defaultJob, bankAccount, role` → ระบบสร้างโปรไฟล์ + บัญชี login (รหัสเริ่มต้น = รหัสพนักงาน,
  `mustChangePassword=true`), แสดงสรุปว่าเพิ่มสำเร็จ/ซ้ำ/ผิดพลาดกี่รายการ
- **หมายเหตุเทคนิค:** การสร้างบัญชี Firebase Auth หลายรายการจากฝั่ง browser ทำผ่าน Firebase app
  instance ตัวที่สอง เพื่อไม่ให้ session ของแอดมินหลุด (ถ้าจำนวนพนักงานมากหรือต้องการความเสถียรกว่านี้
  ค่อยพิจารณาเพิ่ม Cloud Function เล็กๆ ด้วย Admin SDK ภายหลัง — ดูข้อ 11)

## 11. ความเสี่ยง / สิ่งที่ต้องยืนยันก่อนลงมือ
1. **รายชื่อบริษัท/สังกัด ที่ต้อง seed** — มีกี่แห่ง และชื่อ+ที่อยู่เต็มของแต่ละแห่ง (อย่างน้อย โกลบ ซินดิเคท (ประเทศไทย) จำกัด + เบสท์ เอช อาร์ เอ็ม จำกัด)
2. **สูตร "จำนวนเงินรวม"** — ยืนยัน = ก่อนหัก − หัก3% (default; แก้เองได้ผ่านปุ่ม override)
3. **คอลัมน์ไฟล์ CSV** — ยืนยันชื่อ/ลำดับคอลัมน์ตามข้อ 8.1 หรือมีรูปแบบไฟล์เดิมที่ต้องรองรับ
4. **ใครเป็นแอดมินคนแรก** — ต้องตั้งบัญชี admin เริ่มต้น 1 บัญชี (ผู้ใช้ตั้งเองผ่าน Firebase console/สคริปต์)
5. **การสร้างบัญชีจำนวนมาก** — ถ้า import พนักงานจำนวนมาก อาจต้องใช้ Cloud Function + Admin SDK แทนวิธี client (ดูข้อ 8.1)
6. **บัญชี Firebase** — มีโปรเจคอยู่แล้วหรือสร้างใหม่ (ใครเป็นเจ้าของ/จ่ายเงิน)
